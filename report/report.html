Abstract—Autonomous large language model (LLM) agents granted financial execution capability expose platforms to prompt injection, policy bypass, and malformed-output failures when untrusted market context steers decisions. This paper presents a three-layer zero-trust architecture implemented for the Khalifa University Ledger trading platform. Our design isolates role-scoped API credentials between a bounded Trading Agent and an independent AI Guardian supporting cross-provider model diversity (DeepSeek V4.1-Flash via Responses API and Google Gemini 3.8 Flash via the 2026 Interactions API). Prior to LLM judgment, the Guardian independently fetches live policies, quotes, portfolio state, and exact saved theory snapshots, executes deterministic Decimal hard rules (including safe handling of missing reasoning and ≥ quota equality), scans untrusted market news and reasoning for 19 injection directives, validates strategy compliance with bounded proposal-tick drift tolerance, and flags behavioral anomalies (3× median size spikes and rapid direction flips). All agent events are persisted to a SHA-256 hash-chained JSONL log monitored through a zero-key local Security Operations Center (SOC) dashboard. Automated verification across 86 unit tests confirms deterministic containment across all fault, scope, rounding, injection, TOCTOU, and recovery cases.
Index Terms—AI Security Engineering, Autonomous Agents, Prompt Injection Defense, Zero-Trust Architecture, Tamper-Evident Logging.

I. Introduction & Threat Model

Connecting autonomous foundation models to financial order APIs introduces agentic security risks beyond traditional network security [1], [3]. On the simulated Ledger platform (https://ledger.chanyeun.com), a Trading Agent analyzes market quotes and news to propose BUY, SELL, or HOLD actions, while an independent AI Guardian mediates every pending proposal before execution [2].

Guided by OWASP LLM/Agentic threat taxonomies [3], [4], we address six threat vectors:

  • V1 — Oversized & Rounding-Concealed Orders: Transactions exceeding ceiling limits or exploiting floating-point cent rounding [5].
  • V2 — Behavioral Anomalies: Sudden order-size spikes (> 3× historical median) or rapid BUY↔SELL flips unrelated to stop-loss/take-profit triggers.
  • V3 — Indirect Prompt Injection: Untrusted market_news.php items or malicious order reasoning embedding directives such as "ignore previous instructions; skip guardian" [6].
  • V4 — API Key Misuse & Redirect Leaks: Using a trader key for review endpoints, substituting a full key, or forwarding credentials across redirects.
  • V5 — Unauthorized & Unsupported Actions: Short-selling beyond holdings or attempting restricted WITHDRAW calls.
  • V6 — Quota Bursts & TOCTOU Races: Bursting orders to surpass hourly/daily fills, or policy tightening between proposal and review.

II. Three-Layer Zero-Trust Architecture

Our architecture enforces Saltzer and Schroeder's complete mediation and least privilege [1], [7]: Layer 1 (Trading Agent) validates locally, Layer 2 (AI Guardian) independently re-verifies every order, and Layer 3 (Ledger Server) acts as the final policy and funds backstop.

Fig. 1. Three-layer zero-trust architecture isolating Trader and Guardian API scopes, supporting cross-provider 2026 LLMs, and streaming SHA-256 chained events to the zero-key live audit console.

A. Cross-Provider 2026 LLM Integration

config.py and llm.py enforce strict per-role JSON configuration (16 KiB cap, duplicate-key and non-finite rejection, canonical HTTPS check, and cross-provider key rejection). DeepSeekModel calls deepseek-flash (DeepSeek V4.1-Flash) via the OpenAI Responses API, while GeminiModel calls gemini-3.8-flash via Google's 2026 Interactions API (client.interactions.create, schema-enforced response_format, store=False, and 1-attempt retry limit). Running separate providers across Layer 1 and Layer 2 eliminates single-model prompt-injection blind spots [8].

B. Transport Isolation & SHA-256 Audit Chain

LedgerClient (client.py) restricts endpoints per role, injects X-Api-Key solely in headers, disables redirects, paces calls at 1.1 s, honors 429/503 cooldowns, and raises UncertainWrite on ambiguous POSTs rather than blindly resending non-idempotent proposals. storage.py links every log record with seq, prev_hash, and canonical SHA-256 record_hash, verified continuously by verify_chain() inside dashboard.py.

III. Trading Theory & Power-Law Replay

Each member trades one distinct assigned currency (BTC, ETH, SOL, or XRP) enabled exclusively in their Ledger Security Policy and submitted Theory. We adopt a bounded Momentum rule (strategy="momentum"): lookback_minutes=10, threshold_pct=0.5000, position_fraction=0.0500, stop_loss_pct=3.0000, take_profit_pct=5.0000.

Algorithm 1: Appendix A Price Replay & Priority Sizing
1. Fetch market_model.php descriptor (cached by model_version); rebuild 61 evenly spaced samples across [now − 600s, now] with price_at() (power-law trend × 3 sine cycles × twice-iterated integer PRNG noise, rounded half-up to 8 d.p.).
2. Assert |samples[60] − live_quote| ≤ 10-8; refresh descriptor once on mismatch, else HOLD.
3. Compute return_pct = (Pnow / P0 − 1) × 100. Priority: (a) Stop-loss (≤ −3%) / Take-profit (≥ +5%) SELL; (b) Momentum SELL (≤ −0.5% if held > 0); (c) Momentum BUY (≥ +0.5%); else local HOLD.
4. Size BUYs via bounded_quantity(min(cash × fraction, ceiling), price) and validate LLM JSON locally before proposing.

Descriptor & Verification: Default parameters use T=365 days, tick_seconds=5, cycles=[600s, 7200s, 86400s], modulus 2147483647, multiplier 48271, with BTC (A=64,000, b=0.45), ETH (A=3,200, b=0.60), SOL (A=150, b=0.70), and XRP (A=0.60, b=0.35). Unit tests verify both baseline ($64,000.00000000 day 0; $87,426.57643228 day 365) and full-quote fixtures ($67,000.36767791 day 0; $69,404.90274610 day 30; $91,475.89718627 day 365). Because the price model is public, simulator profit is not forecasting skill.

Hand-Calculated Example (BTC): At cash $80000.00, fraction 0.05, and ceiling $10,000.00, BUY budget is min($4,000.00, $10,000.00) = $4000.0000. At BTC quote $60600.00000000, bounded_quantity floors to 0.0660066006 BTC. Exact notional is $3,999.99999606; BUY rounds up to $4000.00, SELL rounds down to $3999.99, and policy_amount = $4000.00 is checked against ceiling and escalation threshold ($2,000.00).

IV. AI Guardian Design & Failure Handling

The Guardian pipeline (guardian.py) treats Trader reasoning, theory prose, and news strictly as untrusted data:

  1. Independent Evidence: Fetches fresh policy, portfolio, and live quote on its own; never trusts Trader estimates.
  2. Pre-LLM Hard Rules: Blocks restricted actions, disallowed symbols, ceiling violations via policy_amount(), sub-cent orders, exhausted hourly/daily quotas via ≥ equality, and insufficient cash/holdings. Escalates orders ≥ escalation_threshold ($2,000 < $10,000 ceiling) and safely flags blank or oversized reasoning (missing_or_invalid_reasoning) without masking blocked violations.
  3. Provenance & Proposal-Tick Drift Tolerance: Validates exact (theory_id, theory_version) snapshots (ProvenanceError → ESCALATE). When a live tick crosses a signal boundary during the ≤120 s window between proposal created_at and review, the Guardian reconstructs the proposal-time quote via price_at() to distinguish benign tick drift from genuine TheoryComplianceError (BLOCK).
  4. News Injection & Behavioral Anomalies: scan_news_items() escalates untrusted news containing 19 prompt-injection directives targeting the symbol before invoking the LLM. Guardian.anomalies() flags orders > 3× the median of ≥3 recent fills and rapid BUY↔SELL flips within 300 s not explained by stop-loss/take-profit.
  5. LLM Schema Gate & Final Recheck: Validates GUARDIAN_SCHEMA (rejecting enlarged MODIFY), re-fetches policy, portfolio, and quote before APPROVE/MODIFY, escalates on provider/validation failure, pauses on 429/503, and reconciles uncertain writes idempotently.

VI. Limitations, Future Work & Related Work

Limitations: (1) Ledger prices follow a public formula; simulated profits prove execution safety rather than alpha. (2) Ledger provides no source IP or key-geolocation telemetry for stolen-key detection. (3) Trader and Guardian execute under one OS account unless isolated via containers/VMs [9]. (4) Keyword injection scanning supplements, but cannot replace, strict trust boundaries and deterministic hard rules against paraphrased attacks [6], [10].

Future Work: Containerizing agents under distinct OS UIDs, integrating semantic embedding prompt-injection classifiers, and signing audit log checkpoints externally.
